# 企业级智能旅行助手目录结构

> 本文档说明前端、API 后端与 Agent 服务分离后的工程组织方式。  
> 依据《企业级智能旅行助手技术选型》与《远程工具沙箱与真实只读接入基线》编写；不包含具体业务代码。

## 1. 分离原则

系统拆分为三个业务运行单元，并增加一个不对浏览器开放的受限工具安全单元：

1. **前端应用**：React 19 + Vite，负责账号密码 Cookie 会话 UI、会话退出、SSE 展示、状态轮询和人工审批交互；不直接访问 PostgreSQL、Redis、百炼或外部差旅供应商。
2. **API 后端服务**：FastAPI，负责 Cookie/CSRF、用户会话、请求校验、统一响应、SSE 网关和运行状态查询；不持有 Agent 的推理流程。
3. **Agent 服务**：FastAPI + LangGraph，负责 L1/L2/L3 意图识别、Master Agent、业务子 Agent、ReAct 工具、百炼模型/记忆库/RAG、HITL 中断恢复；不承载前端页面和用户鉴权页面逻辑。
4. **Tool Gateway / Egress Proxy**：仅承接远程 HTTP MCP、Skill 与百炼出网；按 Provider、域名、路径、操作语义和数据策略白名单放行，不开放浏览器入口，所有写操作默认拒绝。

API 后端与 Agent 服务之间使用版本化内部协议：API 后端提交 `start`、`resume` 或 `cancel` 命令，Agent 服务返回运行状态和事件流。`thread_id`、`run_id`、`request_id`、`user_id` 和角色必须贯穿两边；Agent 服务必须重新校验用户归属与角色，不能盲信客户端字段。`suspend_user_memory` 仅作为非 P0 技术预留。

## 3. 依赖与通信边界

```text
前端 Web
   │ 外部 HTTPS / SSE
   ▼
API 后端 ──内部 HTTPS/HTTP 命令──► Agent 服务
   │                                  │
   ├── PostgreSQL（业务事实/审计）      ├── Redis（checkpoint/事件）
   └── Redis（事件短缓存/限流）          ├── 百炼 API/记忆库/知识检索
                                      └── Python Skills/MCP/供应商系统
```

- 前端只依赖 API 后端的 OpenAPI；不引用 Agent 服务的 Python 包。
- 浏览器通过 HttpOnly、Secure、SameSite Cookie 与 API Server 建立会话；前端不保存令牌，状态变更请求由 API Server 校验 CSRF。
- API 后端只依赖 `packages/contracts` 生成的协议类型和内部 Agent Client；不导入 LangGraph、DashScope 或 MCP SDK。
- Agent 服务只接受来自 API 后端的内部命令，并根据服务端上下文重建 `thread_id`；不直接暴露给浏览器。
- `packages/contracts` 只保存 OpenAPI、JSON Schema 和生成类型，不放共享业务实现，避免前后端或 Agent 形成隐式耦合。
- API 后端负责把 Agent 事件转发为前端 SSE；Agent 服务负责产生事件，不感知 React/Vue 组件。

## 4. 部署建议

开发环境使用仓库根目录的 `docker/compose.dev.yml` 通过 `docker compose` 启动三个业务应用与 Tool Gateway；Egress Proxy 默认拒绝所有未登记出网。生产环境至少拆为 `web`、`api-server`、`agent-server`、`tool-gateway` 四个 Deployment。API 服务可按 HTTP/SSE 连接数扩容，Agent 服务可按模型调用并发和工具吞吐独立扩容。Cookie 的 HTTPS、SameSite、CSRF 与跨域配置必须随最终部署拓扑评审。PostgreSQL、Redis、百炼 API 凭据通过平台托管，不写入代码仓库。

Agent 服务发生中断时，API 后端仍可查询 PostgreSQL 中的运行索引，并从 Redis 的事件缓存补发状态；SSE 连接断开不代表 Agent run 被取消。

## 5. Spec Kit 文档与任务治理

- `docs/` 保存跨 Feature 的产品、技术和工程基线；其中[分阶段实施与测试执行步骤](./企业级智能旅行助手分阶段实施与测试执行步骤.md)是当前闭环实施入口。已确认移除 `specs/` 目录，规格、计划、任务与验收基线均以 `docs/` 和 `packages/contracts/` 中的受版本控制内容为准。
- 实现前先核对需求、技术选型、目录结构和分阶段实施文档；REST、SSE 与 API→Agent 命令字段以 `packages/contracts/` 中的契约为准。
- 任务按“初始化 → 基础能力与工具沙箱 → US1 账号登录 → US2 会话恢复 → US3 意图 → US4 只读旅行 → US5 SSE → US6 写操作拒绝/HITL → US7 审计 → 门禁整合”执行。每个用户故事先编写测试并独立验收，再进入下一交付阶段。
- G1～G9 未确认前，只能创建端口、测试替身、契约、工具沙箱、默认拒绝策略和界面占位；不得创建未经局部解锁的物理 Schema、真实百炼/供应商调用、真实写工具、生产日志平台或容量发布配置。G7 当前仅允许 P0 七张 PostgreSQL 表。
