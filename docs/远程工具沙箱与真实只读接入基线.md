# 远程工具沙箱与真实只读接入基线

> 文档状态：已确认的安全实施基线，优先级高于此前文档中“P0 默认使用 Fake 外部能力”的表述。  
> 生效日期：2026-08-17。  
> 适用范围：百炼 API、远程 HTTP MCP、远程 HTTP Skill，以及调用这些能力的 Agent 工具链。

## 1. 已确认范围

1. 外部工具以**远程 HTTP 服务**形式接入，不执行模型生成的任意本地代码，不运行未受控的 stdio MCP。
2. 本地开发和联调运行模式改为 `real_readonly`：真实只读能力允许经门禁、网关和沙箱策略接入；没有完整配置时必须**拒绝调用**，不得以 Fake 返回冒充真实结果。
3. 所有外部写操作永久保持禁用，包含预订、占座、下单、改签、取消、退款、支付、报销提交、通知发送及供应商侧状态变更。
4. 单元测试可使用测试替身验证边界，但测试替身不是本地联调的默认外部能力。
5. 真实凭据不得提交到仓库、前端、Agent 状态、SSE、日志或普通业务容器；不得在聊天消息中提供真实密钥。

## 2. 安全默认值

| 项目 | 默认值 | 说明 |
| --- | --- | --- |
| 运行模式 | `real_readonly` | 无完整配置时工具请求返回“未配置/策略拒绝”，不回退 Fake。 |
| 工具白名单 | 空 | 未登记的 `provider + path + method + operation` 一律拒绝。 |
| 域名白名单 | 空 | 仅 Egress Proxy 可对外；无显式域名时拒绝出网。 |
| HTTP 重定向 | 禁止跟随 | 防止跳转到白名单之外的地址。 |
| TLS | 强制校验 | 禁止跳过证书验证。 |
| 请求超时 | 连接 3 秒、读取 10 秒、总时限 15 秒 | 仅网络瞬态错误允许有限退避重试。 |
| 并发与响应大小 | 单实例最多 4 个工具请求、最大 1 MiB 响应体 | 超出时安全失败并记录脱敏摘要。 |
| 写操作 | `deny` | 不因 HTTP 方法为 `POST` 而自动拒绝或放行；按已登记操作语义判定，当前写语义全部拒绝。 |
| 凭据注入 | Docker Secret 优先；本地仅未提交 `.env` | 凭据只挂载到 Tool Gateway，日志只记录凭据引用名。 |

## 3. 远程 HTTP 工具的隔离架构

```text
Agent Server
   │ 仅调用内部 Tool Gateway
   ▼
Tool Gateway（非 root、只读根文件系统、受限 PID/IPC、无宿主机挂载）
   │ 仅可访问内部 Egress Proxy
   ▼
Egress Proxy（域名白名单、方法/路径策略、审计）
   │ 仅允许已登记 HTTPS 域名
   ▼
百炼 API / 远程 HTTP MCP / 远程 HTTP Skill
```

远程 MCP 服务运行在服务商侧，因此本地无法隔离其远端进程。沙箱保证的是：本地 Agent、Gateway 和工具请求不能绕过策略访问任意主机、宿主机文件、Docker Socket 或其他进程命名空间。

### 3.1 容器强制限制

- Tool Gateway 使用独立 PID、IPC 和网络命名空间；绝不设置 `pid: host`、`ipc: host` 或共享其他服务进程。
- 不挂载 `/var/run/docker.sock`、宿主机目录、SSH Socket、云元数据 Socket 或包含业务凭据的目录。
- 以非 root 用户运行，`read_only: true`，仅提供受大小限制的 `tmpfs` 临时目录。
- 设置 `cap_drop: [ALL]`、`no-new-privileges:true`、默认 seccomp、CPU/内存/进程数/超时/并发上限。
- Tool Gateway 不直接连接公网；仅 Egress Proxy 具备对外网络，Proxy 按域名和操作白名单放行。
- Docker Compose 只能实现开发级隔离；生产环境必须在 Kubernetes NetworkPolicy、云防火墙或等价网络策略中再次强制执行同一白名单。

## 4. Provider 注册契约

每个真实 Provider 必须以版本化配置登记以下字段，缺任何字段均不可启用：

| 字段 | 说明 |
| --- | --- |
| `provider_key` / `version` | 稳定 Provider 标识与契约版本。 |
| `base_url` / `allowed_hosts` | HTTPS 基地址与精确域名白名单。 |
| `operations` | 每项的名称、路径、HTTP 方法、只读语义、请求/响应 Schema、超时和最大响应体。 |
| `auth_secret_ref` | Docker Secret 或密钥管理服务引用，不得存放明文。 |
| `data_classification` | 可发送字段、禁止字段、脱敏和保留规则。 |
| `rate_limit` / `cost_limit` | 调用频率、并发与成本上限。 |
| `owner` / `approval` | 责任人、供应商授权和复核记录。 |

## 5. 门禁调整

- **G3**：允许实现 Tool Gateway、Egress Proxy、远程 HTTP Provider 契约和“默认拒绝”测试；只有具体 Provider 登记、域名、只读操作、凭据引用、数据边界和供应商授权完整后，才可局部启用真实只读调用。
- **G4**：当前范围明确为“所有写操作拒绝”，因此不得实现或配置任何真实写 Provider。
- **G5/G6**：百炼真实调用仍需确认模型/Embedding 版本、地域、记忆/RAG Scope、数据边界、配额、成本与 Agent 参数；未完成前 Gateway 必须拒绝百炼请求。
- **G8/G9**：本地可记录脱敏审计和做故障演练，但不代表生产日志保留、容量或可用性结论。

## 6. 接入与验收顺序

1. 先实现 `Tool Gateway + Egress Proxy + Provider Registry`，并在无 Provider 配置时验证默认拒绝。
2. 为每个 Provider 编写白名单、写操作拒绝、域名绕过、重定向、超时、超大响应、凭据不落日志和网络隔离测试。
3. 录入一个脱敏测试 Provider；仅在其 G3/G5 局部证据完整后启用真实只读请求。
4. 记录真实请求的 `trace_id`、Provider 版本、脱敏响应摘要、耗时、状态和成本字段；不得记录明文密钥、完整提示词或未经脱敏个人文本。
5. 真实写操作始终保持拒绝；如未来范围改变，必须先重新确认 G4，并新增审批矩阵、幂等与补偿验收。

## 7. 尚待提供的信息

真实调用前仍需提供具体域名、Provider 契约、凭据引用方式、可发送数据字段、百炼模型/知识库/记忆库标识及成本上限。缺失这些信息时系统是“安全禁用”，不是“Fake 成功”。
